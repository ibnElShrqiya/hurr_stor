# متجر حُرّ HURR

متجر عربي متعدد الصفحات ولوحة إدارة. تم تحويل طبقة الاتصال من Firebase إلى Supabase، مع الحفاظ على واجهة HTML/CSS/JavaScript الحالية.

## إعداد Supabase

1. افتح `js/config/supabase-client.js`.
2. قيمة Project URL مضبوطة على `https://axbumspgqeauqtjrqezu.supabase.co`.
3. استبدل `PASTE_YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY_HERE` بالمفتاح العام `Publishable key` أو `anon` من إعدادات مشروع Supabase. لا تستخدم `service_role` أو `secret key` في الواجهة.
4. راجع `SUPABASE-SETUP.md` للتأكد من أسماء الجداول وRLS.
5. شغّل الموقع عبر HTTPS أو خادم محلي، وليس `file://`.

## الجداول التي يتوقعها الكود

`products`, `categories`, `offers`, `coupons`, `shipping`, `settings`, `orders`, `admins`. الكود يتوقع عمود `id` كمفتاح لكل جدول (وجدول `shipping` يستخدم اسم المحافظة كمعرّف في الخدمة الحالية)، وأعمدة البيانات التي تستخدمها صفحات الإدارة. إذا كانت جداولك الحالية تستخدم أسماء أعمدة مختلفة، يجب مواءمة الخدمات معها قبل التشغيل.

## دخول المدير

فعّل Email provider في Supabase Auth وأنشئ مستخدم المدير. أضف سجلًا في جدول `admins` بحيث يكون `id` هو نفس UUID للمستخدم في `auth.users`، والحقل `role` قيمته `admin`. لا تسمح للزوار بإضافة أو تعديل سجلات `admins`.

## تنبيه

هذا الملف يجهّز اتصال العميل ويحوّل الخدمات البرمجية، لكنه لا يثبت أن الاتصال الحي يعمل قبل إضافة المفتاح العام ومطابقة مخطط الجداول وسياسات RLS في مشروعك. كما أن إنشاء الطلب من المتصفح لا يوفر تحققًا خادميًا موثوقًا للأسعار والمخزون والكوبونات؛ راجع الطلبات يدويًا قبل تأكيدها تجاريًا.
